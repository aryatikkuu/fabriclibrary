# Supabase Setup

Takes ~15 minutes from zero to a working backend.

## 1. Create the project

1. Sign in at [supabase.com](https://supabase.com) → **New project**.
2. Pick a region close to your team (e.g. `ap-southeast-1` for Malaysia/Singapore).
3. Save the database password somewhere safe (you rarely need it, but keep it).

## 2. Collect the keys

**Project Settings → API:**

| Setting page value | Goes into `.env.local` as |
|---|---|
| Project URL | `NEXT_PUBLIC_SUPABASE_URL` |
| `anon` public key | `NEXT_PUBLIC_SUPABASE_ANON_KEY` |
| `service_role` secret key | `SUPABASE_SERVICE_ROLE_KEY` |

> The service-role key bypasses Row Level Security. It is only read server-side (`lib/supabase/admin.ts`) — never expose it in the browser or commit it.

## 3. Run the migrations

**SQL Editor → New query**, then paste and run each file **in order**:

1. `database/migrations/0001_initial_schema.sql`
2. `database/migrations/0002_row_level_security.sql`
3. `database/migrations/0003_storage_bucket.sql`

Each is idempotent enough to re-run safely on a fresh project. Verify under **Table Editor**: you should see `mills`, `fabrics`, `fabric_images`, `fabric_documents`, `fabric_tags`, `fabric_similarities`, `ai_extraction_logs`, `profiles`, `audit_logs`, and a `textile-library` bucket under **Storage**.

> Prefer the CLI? `supabase db push` with these files in `supabase/migrations/` works the same way.

## 4. Seed the data

From the project root (with `.env.local` filled in):

```bash
npm run db:seed
```

This upserts the three mills (Masood Textile Mills, Banswara Syntex, Orbit Exports) and eight sample fabrics — two of them deliberately low-confidence so the Review Queue has content. Alternatively paste `database/seed/seed.sql` into the SQL editor.

## 5. Create your first admin

1. **Authentication → Users → Add user** → enter your email + password ("Auto confirm" on).
2. The `handle_new_user` trigger creates a matching `profiles` row with role `viewer`.
3. Promote yourself — SQL editor:

```sql
update public.profiles set role = 'admin' where email = 'you@example.com';
```

4. Sign in at `/login`. You should now see the **Review** link in the header.

Add editors the same way with `role = 'editor'`.

## 6. Storage checks

- Bucket `textile-library` is **public-read** (fabric photos are the website), write-restricted to staff/service role by the policies in migration 0003.
- Files land at `mills/{mill-slug}/fabrics/{CODE}/images/…` — generated by `lib/config/storage.config.ts`, never hand-built.
- If you rename the bucket, set `STORAGE_BUCKET_NAME` accordingly.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| Site shows no fabrics, but rows exist | They're `needs_review` — approve them, or you're hitting RLS as anonymous (expected) |
| `permission denied for table …` | Migration 0002 not run, or you're querying with anon key where staff is required |
| Seed script fails with "Missing …" | `.env.local` not filled in / not in project root |
| Images 404 | Bucket private or `public_url` empty — re-run migration 0003 |
| New signup can't do anything | Correct — default role is `viewer`; promote in `profiles` |
